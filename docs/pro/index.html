为什么这件事不能靠肉眼

插件的攻击面不在 README 里，而在几个固定的位置：cordis.patch.yml 能往插件树里注入条目； client.mjs 跑在浏览器侧，能读你页面里的东西；profile 配置能被改写；依赖可以是远程动态加载的。 这些都不是"看一眼代码"能覆盖的。

DShScan 把这几类位置做成固定规则，每条 finding 带证据与修复建议——不是给一个分数就完事。

常见问题

为什么开源免费版继续免费，Pro 却要收钱？

免费版是 CLI 与规则引擎，MIT，永久免费，不会因为 Pro 上线而收窄。Pro 收的是两样持续投入的东西： 情报（每月新增的恶意模式规则、当月绕过手法简报）和团队策略基线（多仓一致的 ignore / severity 配置与例外登记）。 不是一次性代码，是有人一直在跟。

license 怎么工作？会不会偷偷联网？

离线 Ed25519 签名 license：一个文件，本地验签，不登录、不联网、不上报。断网环境（CI 常见）可用。

扫描器报错了，算谁的责任？

不算任何人的。DShScan 输出的是自动化检测结果，不构成安全审计意见，也不构成"这个插件是安全的"的承诺。 每条 finding 都附证据与修复建议，供你自己判断。规则永远有漏报，这也是它持续更新的原因。

误报太多怎么办？

Pro 的策略包可以做 ignore / severity 覆盖，把团队认可为噪音的规则压下去，并把这份策略提交进仓库——换人也不丢。
